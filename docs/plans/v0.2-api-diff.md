# v0.1.2 → v0.2 API diff — probe results (Issue #17)

**Probed:** 2026-07-04 against the **live v0.2 node on Sneg** (`127.0.0.1:8080`), height 11708, tip slot 345208.
**Cross-ref:** `~/basecamp/refs/logos-blockchain-block-explorer-template/src` (decode reference) and the already-working v0.2 dashboard `~/logos-blockchain-runbook/dashboard/server.py` (Sneg :8090).
**Rule:** every row below is an *observed* response, not an inferred one.

> **Headline:** the node API is `/cryptarchia/*` + `/network/*` + `/wallet/*` (the `/channel` + `/api/v1/...` surface from #11 belongs to the *block-explorer app*, **not** the node — both 404 on :8080). Three real breaks: **info payload reshaped**, **block-by-hash moved endpoints**, **inscription encoding changed**. Plus one operational break: the **zone-scanner is dead-locked on stale pre-fork state**.

---

## 1. `GET /cryptarchia/info` — RESHAPED ⚠️ (breaks scanner + server + publish)

**v0.1.2 assumed** (flat): `{slot, mode:"Online"|"Bootstrapping", height, tip, lib}`
**v0.2 actual** (nested):
```json
{
  "cryptarchia_info": { "lib": "df70…", "lib_slot": 342052,
                        "tip": "4024…", "slot": 345208, "height": 11708 },
  "mode": { "Started": "Online" }
}
```
Breaks:
- **`slot` moved** to `cryptarchia_info.slot`. → zone-scanner strict `Info{slot}` deserialize (`zone-scanner/src/main.rs:250-262`) **fails**; `publish.py:86` / `server.py:1156` `.get("slot")` return None.
- **`mode` is now an object** `{"Started":"Online"}`, not a string. → `server.py:274-286` `chain["mode"] == "Online"` **never matches**.
- **NEW `lib` + `lib_slot`** = last-irreversible-block anchor → this is the **finalization boundary** for the `pending/safe/finalized` model (a block is *finalized* when `slot ≤ lib_slot`).

**Reference fix** — explorer's `normalize_info_payload()` (`node/api/http.py:24-36`): unwrap `cryptarchia_info`, and collapse nested `mode` by taking the innermost value until it's a string.

## 2. Block-by-hash — ENDPOINT MOVED ⚠️ (breaks publish + server block detail)

| | v0.1.2 (current code) | v0.2 (observed) |
|---|---|---|
| Block by hash | `POST /storage/block` body=`"<hash>"` | **`GET /cryptarchia/blocks/{hash}`** (hash as path segment) → **HTTP 200** |
| Blocks by slot range | `GET /cryptarchia/blocks?slot_from=&slot_to=` | **gone** — returns `[]` (empty) |
| Block stream | — | **NEW** `GET /cryptarchia/events/blocks/stream` |
| Headers | `GET /cryptarchia/headers?limit=N` | **unchanged** — array of hash strings ✓ |

Observed: `POST /storage/block` → **404** for both tip and lib hashes. `GET /cryptarchia/blocks/{tip}` → **200**, full block. So the walk pattern becomes **`headers` → `GET /cryptarchia/blocks/{hash}`** (source: explorer `ENDPOINT_BLOCK_BY_HASH = "cryptarchia/blocks/"`, `node/api/http.py:43`).

**Block shape (observed, opcode-17 block):**
```
header: { id, parent_block(NEW), slot, block_root,
          proof_of_leadership: { proof, entropy_contribution, leader_key, voucher_cm } }
transactions: [ { mantle_tx: { hash, ops: [ { opcode, payload } ] } } ]
```
`header.slot`, `header.block_root`, `header.proof_of_leadership.leader_key`, `tx.mantle_tx.hash`, `tx.mantle_tx.ops[].opcode` — **all still present** ✓. New: `header.parent_block`.

## 3. Mantle op model — opcode 17 SURVIVES, encoding CHANGED ⚠️

Opcodes (source: explorer `serializers/operation.py:16-21`, confirmed against live block):

| opcode | op | relevance |
|---|---|---|
| 0 | Ledger (inputs→outputs) | faucet/transfer + stake (`publish.py:705-722`) |
| 16 | Channel set-keys | NEW — channel key mgmt |
| **17** | **ChannelInscribe** | **zone-board inscription — still 17** ✓ |
| 32 | SDP declare service | NEW |
| 34 | SDP active | NEW |

**opcode-17 payload — observed live:**
```json
{ "opcode": 17,
  "payload": { "channel_id":  "0101…01",   // 32-byte RAW hex (was logos:yolo:<name> hex)
               "inscription": "6d15…03…",   // HEX STRING (was JSON int-array) }}
```
Full v0.2 `ChannelInscribeOp` fields (explorer `operation.py:58-66`): `channel_id`, `inscription`, **`parent`** (parent inscription hash, NEW), **`signer`** (pubkey, NEW).

Breaks in this repo's parser (`zone-scanner/src/main.rs`, `publish.py:817-915`):
- **Channel naming**: `YOLO_HEX = "6c6f676f733a796f6c6f3a"` (`logos:yolo:`) prefix decode (`main.rs:18,55-67`) — v0.2 `channel_id` is a raw 32-byte topic hash, **no `logos:yolo:` prefix**. Sender resolution now needs the v0.2 channel→name scheme (see `runbook/dashboard/server.py:86 decode_zone_channel` / `channel_topic_bytes`).
- **Inscription decode**: int-array→UTF-8 assumption (`main.rs:302-311`) — v0.2 emits a **hex string** on newer nodes (explorer field note: "int array on older nodes, hex string on newer ones"). Parser must accept both.
- opcode 17 + `payload.channel_id`/`payload.inscription` path: **still valid** ✓.

The watch loop skips while `new_tip ≤ scanned_tip` (`main.rs:205`), and 345208 ≤ 3926917 forever → **never scans v0.2**. `zone_scan.json` is 5 weeks stale (mtime 2026-05-29), messages carry pre-fork garbage slots (`2151069309`). This is the "scanned_to=0 bug" from the May-17 halt — now root-caused. **Requires a state reset** (delete `zone_scan_state.json`, let it rebuild — per project rule, never hand-edit).
