# Plan — Migrate the logos.live network-map pipeline to Logos v0.2

**Status:** proposed (epic + issues being filed)
**Created:** 2026-07-04
**Owner:** Fergie
**Relationship to #11:** *complementary, not overlapping.* #11 ("unified v0.2 live
dashboard") is the **forward feature** epic — it *adds* the inscription explorer and
unifies the dashboard, using capabilities v0.2 exposes. **This epic is corrective** — it
makes the *existing* pipeline (crawler, zone-scanner, publish.py, server.py, frontend)
actually align with the v0.2 chain, of which only the node-port bump (8085→8080) is done.
Split rule: **keep-working + modernize the map pipeline here; build-new-explorer in #11.**

---

## Why now

The Logos testnet has forked to **v0.2** (node now serves `127.0.0.1:8080`; new L1 state
model `pending → safe → finalized`; new op/endpoint surface — `ChannelInscribe`,
`/channel/{id}`, `/api/v1/transactions/list?fork=0`). The current pipeline still speaks
**v0.1.2**: its DHT protocol id, bootstrap peers, opcode magic numbers, channel-prefix
scheme, chain-state field names, and every version constant are hardcoded to the old
chain. Symptoms already visible: the beacon emits stale v0.1.2 explorer URLs, and
PROJECT_KNOWLEDGE notes ~90 orphaned pre-fork `zone_scan.json` messages. Left unmigrated,
the map silently degrades (crawler finds zero peers, zone-board stops updating, chain
panel goes stale) rather than erroring loudly.

## Ground truth = the live v0.2 node

Per decision: the authoritative source for *what changed* is the **running v0.2 node on
Sneg** (`127.0.0.1:8080`), cross-referenced with the decode reference
`~/basecamp/refs/logos-blockchain-block-explorer-template`. No inferred shape is treated
as fact until the probe (Issue 1) confirms it. Downstream issues cite the probe's diff.

Mitigation note: the Rust scanner uses tolerant `serde_json::Value` indexing → shape drift
yields **silent empty results**, not crashes (except the strict `Info{slot}`). Python uses
soft `.get`. So the failure mode across the board is *quiet degradation* — the migration's
acceptance must be **positive** (data actually appears), never "no error thrown".

## Issue breakdown (→ GitHub)

1. **Spike — probe v0.2 node, produce the v0.1.2→v0.2 API diff** *(blocks all others)*
2. **Crawler** — v0.2 DHT protocol id + bootstrap peers; reconcile the two peer lists
3. **Zone-scanner** — v0.2 inscription parsing (opcode/`ChannelInscribe`, channel prefix)
4. **publish.py** — chain aggregation, faucet/stake, slot-time, cache reset to v0.2
5. **server.py** — chain-state model + agent API + version constants to v0.2
6. **Frontend** — surface `pending/safe/finalized`, drop v0.1.2 references
7. **Constants + docs sweep** — version strings, runbook paths, architecture/ecosystem docs
8. **Cutover + end-to-end verify on Sneg** — reset orphaned caches, re-scan from v0.2 genesis, confirm every panel live

Dependency: **1 blocks all**; 2–7 largely parallel; **8 is the closing gate**.

## Definition of success (epic-level)

The dashboard is **fully live against the v0.2 node** on Sneg with no v0.1.2 residue:

- [ ] **Crawler** discovers live v0.2 peers (non-zero) → map pins populate.
- [ ] **Zone-scanner** parses v0.2 inscriptions → zone-board messages appear with correct sender / `#geo` / `#live`.
- [ ] **Chain panel** shows correct v0.2 tip/slot and finalization; faucet + stake metrics correct.
- [ ] **Agent endpoints + node-map** reflect the v0.2 `pending→safe→finalized` state model; `chain.mode` handled for v0.2 states.
- [ ] **Frontend** renders v0.2 state; zero stale `v0.1.2` strings/URLs anywhere.
- [ ] **Version constants** (node/circuits/release URLs/manifest port/network label) updated.
- [ ] **Orphaned pre-fork data** cleared; caches reflect the v0.2 chain only.
- [ ] Acceptance is **positive** (data present + correct on the live dashboard), verified on Sneg — not "no error".

## Non-goals (owned by #11)

- Unifying node-map + explorer + zones into one dashboard.
- Beacon 'copy URL' v0.2 format (cross-repo: beacon-basecamp).
